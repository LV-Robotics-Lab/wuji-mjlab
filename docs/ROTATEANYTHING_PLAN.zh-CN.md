# RotateAnything V1 实施计划

状态：设计方案，尚未开始实现或新训练。

相机选型（2026-09-12）：用户确定采用单台 Intel RealSense L515。下述 V1 的完整 mesh／真值位姿实验保留为控制基线；新增 L515 感知阶段，接口与验收见第 11 节。已增加单十二面体 AprilTag 资产、打印图与 RGB-D PPO smoke，见 [L515 / AprilTag 训练说明](L515_APRILTAG_TRAINING.zh-CN.md)。真实相机链路与多物体视觉训练尚未实现或实机验证，V1 仿真指标不代表视觉闭环结果。

## 1. 目标、范围与研究主张

从随机参数初始化一个共享策略，在 mjlab 中驱动同一只 Wuji Hand，将训练时未见过、尺寸适合该手的刚性物体旋转到指定 SO(3) 目标姿态，并持续完成后续目标。所有物体共用 Actor 参数和动作接口，不依赖物体 ID 查找策略。

V1 保留 20 个独立关节动作，不加入 QP、MPC、协同降维或新的关节耦合。既有关节限位、动作裁剪、位置执行器和仿真碰撞照常生效。仅研究仿真中的多物体控制：不包含真实手部署、视觉位姿估计、从桌面拾取、跨机械手迁移、软体和铰接物体。

必须区分两项结果：

1. 给定合理手内初始状态后的旋转泛化。
2. 用统一初始化算法，为新物体建立有效手内状态的覆盖率。

不能只报告筛选后的成功率而隐藏初始化失败。当前十二面体的 128/128 是单物体基线，不能代替跨物体证据；旧权重仅用于回归检查，不作为新策略起点。

## 2. 已核对的代码与首个技术关卡

现有可复用实现：

- `tasks/reorient/mdp/commands.py`：SO(3) 目标与保持/切换状态机。
- `tasks/reorient/mdp/actions.py`：默认关节角偏移、裁剪和 EMA。
- `tasks/reorient/reorient_terms.py`：观测、接触传感器、奖励和终止。
- `tasks/reorient/config/wuji_hand/rsl_rl/ppo.py`：非对称 Actor–Critic PPO。
- `tasks/dodecahedron/`：独立任务注册范例。
- `scripts/dodecahedron_harness.py`：有限性、接触、重置、训练和重载验收。

当前安装 mjlab 1.3.0，现有 EntityCfg 只有单个 spec_fn。官方 mjlab 1.4.0 引入 VariantEntityCfg，可在共享拓扑的并行环境中使用不同网格。world→variant 在仿真初始化时确定，reset 不换 mesh。这意味着 V1 的训练设计是“同一 rollout 批次含多种物体”，而不是承诺每次 reset 动态换网格。[1][2]

首先在独立虚拟环境验证 1.4.0，固定与它兼容的 MuJoCo、Warp、PyTorch、vendored RSL-RL 版本并生成锁定记录；不覆盖已验证的十二面体环境。当前版本下新能力尚未实测。

技术验收顺序：

1. 旧十二面体任务可构建、推理、运行原有相关回归测试。
2. 4 种 mesh 同批运行，逐环境核对物体 ID、实际碰撞形状、质量/惯量和点云。
3. 对照每个资产单独编译的物理量，防止所有物体误用模板物体的惯量。
4. 验证 render 和目标 ghost 显示的是当前 world 对应资产；不能缓存一个 cube_mesh 给全部物体。
5. 跑 32 个变体与至少 512 个环境的 rollout/PPO smoke，检查传感器维度和 reset 隔离。

若迁移在预定的 1–2 个工作日技术排查窗口内仍无法可靠运行，则停止扩大任务，选择最小兼容修复或重新排期；不暗中实现一套手写 geom_dataid 切换。逐物体独立仿真仅作为诊断工具，不作为默认大规模训练方案。

## 3. 物体库与冻结的数据划分

先做 32 个资产的 smoke 集，然后建立 V1 的 500 个正式资产：320 train、80 validation、100 IID test。五组各占 64/16/20，所有参数和随机种子写入 manifest。数量是初始工程配置，进入正式实验前冻结。

五组覆盖：

- 紧凑多面体：盒体、不同面数多面体、截角体、随机凸多面体。
- 圆润体：非球形椭球、胶囊、圆角盒、短圆柱的凸网格近似。
- 扁平体：扁盒、扁椭球、短圆盘；重点覆盖厚度变化和翻面。
- 长条体：较长盒体、胶囊、短棒；V1 先限制在能够手内操控的长宽比。
- 不对称凸体：楔形、偏斜凸包、非对称收缩的凸体；显式验证生成后仍为凸体。

额外建立 100 个 OOD 资产，分成两个固定子集：50 个来自完全留出的生成器/组合方式，50 个来自超出训练区间但仍通过抓握与物理检查的形状参数。它们只用于最终评测，不参加课程调节或模型选择。

所有尺寸变体、同源 mesh 的衍生体先按 source_group 分组再切分；禁止同一个基础 mesh 缩放后跨 train/test。做几何哈希与归一化几何相似度检查，记录近重复处理。IID test 表示新实例；OOD 则另外说明到底留出了哪类生成方式或参数，不能把两种泛化混成一个数。

V1 不以完全球体为核心 SO(3) 指标：对称形状的外观无法唯一确定姿态。使用仿真物体固定坐标系严格评分，并在演示中加轴或编号；可附报对称等价评分，但不替换主指标。碰撞和策略不使用纹理编号。

### 初始物理范围（候选，必须经资产/抓握检查后冻结）

- 以当前 70 mm 外接直径物体为尺度参考，先探索约 45–85 mm 最大尺寸、约 1–2.5 长宽比。
- 质量候选区间 50–180 g；以几何体积与材料密度共同确定基准，再做有限扰动，避免极小物体获得不合理的大质量。
- 单一凸碰撞 mesh；起步控制凸包约 20–128 顶点，以接触准确性和吞吐 profiling 决定上限。
- 尺寸和长宽比编译进资产变体，禁止用简单 geom_size 修改冒充 mesh 缩放。
- 摩擦围绕已验证的接触配置做小范围分级变化。MuJoCo 接触参数优先级可能使物体摩擦被手部覆盖，必须验证实际生效的接触参数，而非只记录配置值。
- 质量、惯量和重心联合保持物理一致性。第一轮先固定重心；后续重心扰动由有效质量分布或经过验证的物理一致随机化实现，不能独立乱采惯量分量。

Manifest 至少包含：object_id、source_group、family、generator_version、seed、split、尺寸、体积、质量、惯量、重心、碰撞 mesh、视觉 mesh、点云路径、几何哈希、有效性检查、初始化覆盖率。原始候选和被排除对象都保留记录。

## 4. 初始抓握：独立的离线构建阶段

不为所有物体强行复用十二面体固定出生位置。为每个资产使用同一套候选生成与短仿真筛选流程：

1. 从多个通用手姿、物体位置和朝向生成候选，避免只使用一个默认弯曲姿态。
2. 检查关节限位、深穿透、物体是否落入可抓握空间；穿透阈值依据接触模型校准。
3. 使用固定、非学习的短时合拢/保持过程，测试物体是否留在手内、状态是否有限、是否有合理多点接触以及动作调整余量。
4. 保存合格的 hand qpos、object pose、速度、接触摘要、稳定时长和候选来源；争取每物体 16–32 个有效状态，并检查朝向多样性。
5. 每次 reset 采样对应资产的合格状态，并做小幅扰动。加入初始化失败检测与计数。

对于 test/OOD 资产，可以用它们的 mesh 运行相同初始化算法，但不得借助训练后策略的旋转成功率筛选起点，也不得逐物体人工调参。评测分别报告初始化覆盖率、条件旋转成功率与将初始化失败计为失败的总体结果。手内状态来源是 V1 的任务前提，不声称实现了从任意场景自主抓取。

## 5. 一个共享 policy 的具体设计

### Actor 输入

- 归一化关节位置、关节速度、位置目标误差。
- 上一步实际执行的动作/平滑后的目标，以及短历史；第一版采用 3 帧，与基线保持可比，必要时再对照 10 帧。
- 物体中心相对掌心的位置。
- 当前物体旋转的 6D 表示、目标旋转的 6D 表示以及相对旋转误差，均使用明确且一致的掌心坐标系。
- 128 个从物体表面面积均匀采样的几何点，变换到当前掌心坐标系。使用固定手尺度归一化，保留物体实际大小；不把每个物体都缩到单位球。

点云取自已知仿真 mesh，不是相机观测；该设定明确称为“已知几何/仿真位姿条件下的泛化”。禁止输入离散 object_id、family_id、split_id 和编号纹理。ID 只用于检索数据、采样和评测分组。

V1 Actor 暂不增加接触输入，避免一开始混入新的信息来源；Critic 可以使用接触状态与力。后续若加入 Actor 接触观测，要作为独立消融，不能把性能提升全归因于几何。

### 网络与动作

PointNet 风格共享逐点 MLP（起步 3→64→128）＋对称最大池化得到 128 维几何特征，与状态/历史拼接，输入 512→256→128 Actor。Critic 采用同类几何编码加原有较宽网络，并接收真实物体线/角速度、接触摘要和当前物理参数。[3]

完整复用 20 维动作语义：默认关节角＋有界偏移，EMA 后送入位置执行器。先保持 20 Hz 策略控制与既有 100 Hz 物理步进。若新几何出现接触不稳定，再以时间步减半实验确定是否需要提高物理频率，保持实际控制周期一致。

几何编码器是可训练模块，必须纳入 PPO optimizer、checkpoint 和推理导出；通过自定义模型类接入 RSL-RL 的网络接口。不能把冻结的随机编码器作为最终方案，也不能随意拼接扁平点云却忽略点序依赖。

数据要处理清楚原始 mesh、MuJoCo 编译后的 mesh 局部变换、物体根坐标系之间的关系，防止视觉、碰撞、观测互不对齐。PointNet 不是默认保证泛化；它是需要与无几何输入对照验证的假设。

## 6. 奖励、成功与终止

保留现有目标状态机作为起点：0.2 rad 内连续 5 控制步算一次成功，随后约 1 秒再切换目标。始终使用 SO(3) 随机目标，V1 不引入复杂角度课程；若直接学习失败，再单独测试较近目标课程。

保留稠密姿态对齐、保持奖励、动作平滑、力矩、自碰撞和掉落项。逐物体检查各奖励的真实量级。现有针对方块/Wuji 手设计的滑动惩罚和 palm_detach 奖励不视为普适真理：起步使用温和权重或禁用掌部脱离奖励，并在验证集检查是否阻碍扁体与长条体。

掉落/逃逸需要按物体尺寸重新验证。不能让大物体仅靠中心仍在 cage 内被误算为稳握，也不能要求整个物体必须被手部 AABB 包住。结合掌心相对位置、物体尺度和持续逃逸时间做判断，以人工构造的保持、正常换指、真实掉落案例校准；短暂失去接触不直接终止。

所有奖励的 step_dt 因子、hold 时间和 timeout 使用统一单位；改变控制频率时要保持时间语义。无隐藏物体专属奖励权重。

## 7. 多物体采样与从零训练

- 固定训练 mesh 库，在一个异构 batch 中同时分配多个物体；先按 family 等额分配，再在 family 内按资产分配。记录真实 world_to_variant 映射和每物体的环境步数。
- world 的 mesh 在进程生命周期内固定；reset 随机化同一物体的初始状态和已验证的物理属性。若阶段间改变资产分配，在 checkpoint 边界重建环境并恢复 optimizer/normalizer；不依赖不存在的 reset 换 mesh API。
- 所有对照均从随机参数开始，不载入十二面体权重。
- 起步 PPO 沿用 lr=1e-4、clip=0.2、gamma=0.99、GAE lambda=0.95、40 步 rollout、4 轮更新。Actor/Critic 正常化不跨不同语义字段盲目混用。
- 环境数先测 512、2048、4096。点云输入和 rollout 存储会增加显存，4096 是目标而不是前提。
- 首先让约 32 个代表资产在固定物理参数下学会；再进入完整训练集；最后逐级加大物理变化。各阶段的目标、采样配置和升级判据单独保存，不能静默改变数据分布。
- 物理扰动强度根据验证结果决定；起步不增加随机外力，避免同时引入太多失败来源。

首轮对照：B0=多物体状态输入 PPO＋相同物理随机化；B1=状态＋几何 PPO＋相同物理随机化；B2=状态＋几何 PPO、无物理随机化。B0/B1 检验几何信息，B1/B2 检验随机化。除被比较项外，训练对象、初始化、奖励、预算和选 checkpoint 的规则一致。

先各跑一个种子筛选工程问题；主对照 B0/B1 至少补齐三个独立训练种子。物体点云、初始状态、目标 RNG 与网络初始化使用分离的随机源。共享策略在新 mesh 上直接推理，不允许用测试对象进行梯度更新。

## 8. 评测协议与建议验收目标

在启动主实验前冻结以下协议。每种训练设置只根据 validation 选择 checkpoint；test/OOD 不用于早停或超参搜索。

### 单目标

- 每个物体固定 20 个初始化/目标 seed；主指标为 10 秒内成功，另报 50 秒内成功用于与旧任务比较。
- 成功必须小于 0.2 rad 且保持 0.25 秒；掉落、超时、仿真异常均进入统计，不从分母移除。
- 100 个 IID test 物体对应每个训练种子 2000 个单目标 trial；OOD 同样独立评测。
- 报告每物体成功率、family 宏平均、整体物体宏平均、最差 family、完成时间中位数/P90，以及失败类型。
- 失败的完成时间是删失数据，不能只对成功样本平均后当作所有 trial 的速度。

### 连续目标

- 每 trial 持续 30 秒，成功后切换新目标。
- 报告不掉落比例、完成目标数、每分钟目标数与难形状失败案例。
- 掉落后不自动重置并继续累加同一次 trial；视频与指标使用同一计数定义。

### 物理泛化

几何 IID/OOD 与物理扰动分开做矩阵：标称物理、训练范围内物理、单项超范围扰动。报告组合失败，不把“新几何＋新摩擦＋新重心”混在一起后无法归因。

建议 V1 验收目标（研究目标，不是效果承诺）：IID 新物体 10 秒宏平均成功率 ≥90%，最差 family ≥70%；OOD 新生成方式/参数宏平均 ≥70%；30 秒连续任务不掉落比例 ≥95%，至少完成 10 个目标的 trial 比例 ≥70%。必须同时报告初始化覆盖率与包含初始化失败的总体指标。

三个训练种子分别报告；统计不确定性按物体分组 bootstrap，不能把同一个物体上大量相关 trial 当成独立物体。最终还应说明 B1 是否比 B0 有稳定优势；若没有，保留更简单方案。

## 9. Harness、里程碑与交付物

M0：冻结协议与清点基线。交付 split 规则、奖励定义、评测指标、已有十二面体回归记录。

M1：新版本与异构仿真关卡。交付独立依赖锁、4/32 物体 smoke、惯量与碰撞/观测一致性证据、GPU profiling。未通过不启动大规模训练。

M2：资产与初始化。交付程序化生成器、manifest、冻结 train/val/test/OOD、有效初始状态库、排除原因和覆盖率。

M3：共享 PPO。交付状态基线与几何模型、训练/加载/确定性推理测试、有限性检查、点云与几何对应检查。先让 32 物体任务产生可靠进展。

M4：完整训练和主对照。交付每个 run 的 commit、配置、依赖、seed、对象集哈希、normalizer、optimizer、checkpoint、step/family 统计。先单种子筛选，再补主对照的三个种子。

M5：冻结评测。交付逐 trial JSONL、按物体汇总、置信区间、连续目标结果、失败案例和多物体 demo。成功视频按预定物体/seed录制，不能只挑最好看的结果。

Harness 分四层：asset → environment → training smoke → evaluation。每层输出可机器读取的结果、阶段状态、错误类别与文件路径；明确区分 infrastructure_pass 与 policy_target_pass。断点恢复和失败要留下日志；不自动启动无限训练，不把 dashboard 不可用当成实验成功。

拟新增模块（尚未创建）：

- `assets/objects/rotateanything/`：生成器、schema、manifest 与几何工厂。
- `tasks/rotateanything/`：独立配置、观测、reset、奖励、按物体评测。
- `rl/models/geometry_actor_critic.py`：PointNet 风格编码与 RSL-RL 接口。
- `scripts/rotateanything/`：资产检查、初始化库、harness、评测与 demo 入口。

大体积生成资产、缓存和训练输出放 ignored 目录；源码、manifest、split、生成版本与校验和纳入版本管理。导出的最终包应能通过一个 task ID 与一个 checkpoint 在 train/validation/test 各资产上运行。

## 10. 算力预算、停止条件与风险

当前单十二面体训练的约 5000×4096×40=8.192 亿环境步，只能作为本机单物体吞吐参考，不能直接推算多物体点云模型耗时。每次主训练先预留 5000 iteration 的起步预算，是否延长到 10000–15000 取决于验证曲线；实际 GPU 小时在 M1 profiling 后确定。比较既报告相同环境步数，也报告相同实际时间下的效果。

单张 GPU 串行运行主要训练；评测使用受控小批次。先确认训练进程和其他任务的显存占用。阶段性验收不通过先修数据/任务，不无条件增加迭代次数。

主要风险与处置：

- 新版本与 vendored RSL-RL 不兼容：独立环境、最小兼容改动、保持旧实验可复现。
- 多物体中少数易物体主导学习：按 family 配额、逐物体曝光与成功率监控，训练集内调整采样，测试集不参与。
- 点云对应错误或规模信息丢失：显式坐标变换和单位检查，逐物体渲染交叉核验。
- 随机化无效/物理不一致：检查实际接触参数和编译后的质量/惯量，不只检查配置。
- 初始化筛选造成幸存者偏差：记录全部候选与覆盖率，固定测试算法并报告总体失败率。
- 部分形状在该手上物理不可操控：明确排除标准并报告范围，不能声称字面意义上的“任何物体”。
- 奖励鼓励稳握却不旋转：分别跟踪姿态进展、连续目标数与动作幅度，检查过强平滑/手姿/滑动惩罚。
- 稳定卡在某 family：用少量该 family 的单物体专家作诊断区分任务不可行与共享策略欠拟合；诊断专家不算最终共享策略。

最终“完成”意味着：共享策略确实在冻结的未见物体集上达到约定指标，且初始化边界、失败和计算成本完整公开。写完代码、跑完 iteration 或只出现一个好视频均不等于这个研究目标完成。

## 11. L515 感知阶段

已实现单十二面体的“仿真 RGB → AprilTag/PnP → 位姿 actor”试验入口 `scripts/train/train_apriltag_pose.py`，完成短 PPO 与低维存储验证。与直接 RGB-D CNN 基线分别保留；最新观测接口、检测失效处理与验证边界见 [L515 / AprilTag 训练说明](L515_APRILTAG_TRAINING.zh-CN.md)。真实 L515 桥接和多物体训练仍未完成。

### 安装与采集

- 单台 L515 固定在手外，先试斜上方观察掌内物体；相机到物体约 0.35–0.60 m 是待实测的起始摆位。官方最小深度距离为 0.25 m，需让运动中的手和物体留出余量，不能把相机贴在掌心附近。[5]
- 起步申请 640×480、30 Hz 深度与设备支持的 30 Hz RGB 配对模式，启动时枚举并记录实际支持和启用的 profile。保留原始帧、内参、畸变、深度比例、RGB/深度外参、帧号、设备时间戳及主机单调接收时间；检查 USB 连接和实际掉帧率。
- 相机采集与现有 20 Hz 控制异步运行；RGB/深度进行时间与几何对齐，控制使用最近可用观测并记录年龄，不把设备时钟直接与主机时钟相减。无效深度保留 mask，不视为真实零距离点。
- 采集进程使用独立环境。以官方最后验证支持 L515 的 librealsense 2.50.0 为兼容起点，配套验证 Python binding、Python 版本、固件与主机系统；最终锁定实测组合，不假定最新 SDK 仍支持该设备。[6]

### 第一阶段：视觉位姿接入现有控制器

管线：L515 RGB-D → 物体检测/分割与位姿追踪 → 手腕 Tag 坐标变换 → 现有 policy。标记物体先复用 ArUco/AprilTag 逻辑验证坐标与时序；十二面体的标记布局需单独定义，不能直接复用方块面模型。无标记物体的追踪器需另行验证。

感知消息至少包含 `position_m[3]`、`quaternion_wxyz[4]`、`frame_id`、采集/接收时间、`valid` 和质量指标。目标姿态与当前物体姿态必须使用同一 Tag 坐标系；掌心坐标输入使用显式标定变换，不能只更改坐标系名称。

兼容实验只替换现有 3 维位置与 6 维旋转误差的来源，保留 207 维 actor 接口。有效性与观测年龄先用于记录和外围失效处理；接入前定义丢失超时与暂停策略，禁止静默无限使用旧位姿。若将这些字段加入 actor，则版本化 observation 并重新训练。

训练的感知扰动应覆盖实测位置/旋转误差、相关偏差、延迟、连续丢帧、遮挡和重获跳变；不以独立随机噪声代替全部相机误差。分别比较真值、模拟追踪误差、L515 实测观测下的效果。

### 第二阶段：相机可见点云策略

actor 输入改为关节/动作历史、目标指令及 L515 可见的局部点云（必要时融合 RGB 特征），禁止继续使用真值变换的完整 mesh 点云或真实物体姿态。物体分割不能依赖部署时不可用的真值 mask；仿真真值可用于监督与单独的理想感知对照。critic 和奖励可保留仿真真值。

仿真相机需匹配标定内外参、视野、遮挡和采样时序，并依据实测加入深度缺失与噪声；随机删掉完整 mesh 上的点不能代替真实单视角可见性。PointNet 点数在采集有效点数与吞吐测量后确定，不能直接假定原方案的 128 点足够。

对完全对称、无可辨识纹理的物体，视觉阶段采用对称等价姿态成功标准；若要求唯一物体坐标系朝向，则必须提供可观测标记/纹理。该结果与 V1 真值坐标系严格评分分别报告。

### 验收顺序

1. 设备枚举与连续采集：记录 SDK/固件/profile、有效深度比例、帧率、掉帧率和时间戳一致性。
2. 静态标定与运动录制：在不同摆位、手指遮挡及转动速度下，测量相对独立参考的位姿误差、延迟 P50/P95、追踪丢失持续时间和重获跳变。仅有追踪器自身输出不能证明精度。
3. 离线回放验证单位、四元数顺序、Tag/掌心变换、缺帧处理及 observation 维度，再进行闭环验证；未达稳定追踪前不启动视觉策略大规模训练。
4. 相机可见点云策略独立训练/评测，报告感知失败、控制失败和总体成功率。接通相机或成功渲染图像不等于消除了 actor 的真值输入。
